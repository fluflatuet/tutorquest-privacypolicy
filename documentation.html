TutorQuest: Math

Technical Documentation v1.3.5 | Production Readiness Phase

1. Project Overview

TutorQuest is an educational Android application designed to transform math practice into a rewarding role-playing adventure for children. Moving beyond static drills, the app allows children to switch between being the Student (solving problems) and the Tutor (grading a companion's work).

Privacy-First & Local-Only Philosophy:
  • No Cloud Storage: All user data, progress, and custom worksheets are stored strictly on the physical device.
  • No Analytics/Tracking: Zero remote telemetry or third-party tracking SDKs are permitted.
  • No Accounts: Children start playing immediately without email registration or account creation.
  • Safe Environment: Strict "Privacy-by-Design" ensures no data leaks to the Android system logs in production.

2. Technology Stack

  • Language: Kotlin (modern functional style, Coroutines/Flow).
  • UI Framework: 100% Jetpack Compose (Material 3). No XML layouts.
  • Database: Room (SQLite) with custom TypeConverters for JSON serialization of math problems.
  • Asset Handling: Native Android painterResource hooks for multi-layered character rendering.
  • State Management: Unidirectional Data Flow (UDF) via StateFlow and MutableSharedFlow.

3. Core Architecture & Data Flow

The project follows a reactive architecture where the UI observes a single source of truth.

  • ViewModel Layer: GameViewModel maintains the GameState. It processes GameEvent intents from the UI and updates the state accordingly.
  • Repository Layer: UserRepository acts as an abstraction layer for the UserDao, handling data persistence and preference management.
  • UDF Loop: User Action → GameEvent → ViewModel → GameState (Immutable) → Compose UI (Recomposition).

4. Database Schema (Room)

The persistent state is managed via three primary entities:

UserProfileEntity

Stores the core profile data, stats, and settings. Key fields include:

  • currencyBalance: Total coins earned.
  • isPremiumUnlocked: Boolean flag for IAP status.
  • customDailyLimit: Nullable Integer. null = Unlimited, Int = Custom cap.
  • todayPapersCommittedCount: Tracks workload for the current date.

user_created_worksheets

Stores "Masterpieces" created by the child in Tutor Mode. Problems are stored as a serialized JSON list via GSON Converters.

unlocked_shop_items

A mapping table tracking which ShopItem IDs have been purchased by which profileId.

5. Domain Logic & Avatar System

The character system uses a Type-Safe Layering Engine defined in AvatarComponent.kt and ShopRegistry.kt.

Clothing Coverage Enum

enum class ClothingCoverage { 
    STANDARD,  // Default (Shirt/Pants/Shoes visible)
    ONESIE,    // Torso + Legs (Hides Bottoms layer)
    FULLBODY   // Full Costume (Hides Body, Hair, Shoes, Accessories)
}

This enum eliminates brittle string matching (checking for "onesie" in filenames). The ShopRegistry maps every ShopItem to its specific ClothingCoverage, ensuring pixel-perfect layering without clipping.

6. Core Features & Mechanics

The Game Loop

Children earn coins (5–100 based on level) by completing worksheets of 5 equations. Correct answers increment global totalEquationsSolved and progress the level bar (3 worksheets to level up).

Daily Limits System

User Tier Enforcement Behavior
Free User Hardcoded 3-Paper Cap Triggers the Premium Purchase Gate upon reaching limit.
Premium User Customizable Limit Default: Unlimited. Parents can set custom caps (5, 10, 20) via Parent Corner.

The Parent Corner & The "Gate"

To access settings, parents must solve a randomized math challenge (e.g., "What is fifteen plus six?"). This ensures children cannot accidentally modify limits or initiate purchases.

The Companion

A dynamic character that reacts with emotions (Surprised, Celebrating, Thinking) based on child performance. It acts as the companion in the learning journey, providing visual feedback and encouragement.

7. Debug & Testing Tools

Features wrapped in BuildConfig.DEBUG to prevent exposure to end-users:

  • TimeProvider: A singleton allowing developers to override the system date. This is used to test seasonal events (Halloween/Christmas) without modifying the Android OS clock.
  • Developer Shop Row: A scrollable row in the shop containing "Time Travel" buttons and a DEV: UNLOCK ALL CLOTHES bypass that populates the database with every registry item ID.
